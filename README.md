# ХРОНО

Локальная веб-игра о датах исторических событий. Игрок угадывает год из четырёх цифр за шесть попыток. Ответ хранится и проверяется на сервере, а браузер получает его только после победы или поражения.

## Быстрый запуск

Нужен Node.js 22.5 или новее. В проекте нет сторонних runtime-зависимостей: SQLite входит в Node.js как `node:sqlite`.

```powershell
cd "C:\Users\Досымжан\Documents\Codex\2026-10-27\new-chat\outputs\hrono"
Copy-Item .env.example .env
npm start
```

Открой `http://127.0.0.1:4173`. Первый запуск создаст `data/hrono.sqlite`, заполнит его вопросами и построит календарь заданий. Устанавливать npm-пакеты не требуется.

Чтобы открыть редактор контента, создай случайный токен и запиши его в `ADMIN_TOKEN` в `.env`:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Перезапусти сервер, открой раздел **Редакторам** и введи тот же токен. Если `ADMIN_TOKEN` не задан, сервер закрывает административные маршруты.

## Что работает

- **Ежедневное задание.** Сервер использует дату UTC. Одинаковая дата закреплена за одним вопросом в таблице `daily_challenges`; расписание заранее создано на 2026–2027 годы. Игровая сессия и попытки сохраняются в SQLite.
- **Архив.** Календарь показывает доступные дни, текущий прогресс и завершённые игры. Есть фильтры по категории и историческому периоду. Даты после серверного «сегодня» не раскрывают вопрос.
- **Бесконечная игра.** Вопрос выбирается на сервере по категории и сложности. Последние 16 тренировочных вопросов исключаются, пока есть другие варианты.
- **Тематические подборки.** 11 редактируемых категорий, включая историю Казахстана и Центральной Азии.
- **Статистика и достижения.** Считаются по сохранённым партиям гостевого профиля, без случайных или глобальных показателей.
- **Ввод.** Цифровая клавиатура, автоматический переход между клетками, стрелки, Backspace, вставка четырёх цифр и отправка Enter. Повторяющиеся цифры сравниваются по алгоритму Wordle.
- **Результат.** После конца игры появляется историческая справка, эпоха, регион и ссылки на источники. Результат можно скопировать, отправить через Web Share или сохранить PNG.
- **Редактор.** Доступ закрыт без `ADMIN_TOKEN`. Можно экспортировать контент, импортировать или обновить события, добавлять категории, увидеть список событий и назначить проверенный опубликованный вопрос на дату. Импорт валидирует год, перевод, категорию и HTTPS-ссылки; дубликаты по названию и году отклоняются.
- **Настройки и приватность.** Тёмная и светлая темы; гостевой прогресс можно удалить. Имя и почта не требуются.

## Структура

```text
server.mjs          HTTP API, логика сессий, планировщик и проверка ответов
public/             Адаптивный интерфейс без внешних runtime-скриптов
data/events.json    Начальный набор вопросов и источников
data/categories.json Категории
data/schema.sql     Схема SQLite
data/hrono.sqlite   Создаётся при запуске; игнорируется Git
test/               Unit- и API-интеграционные проверки
.env.example        Настройки запуска
```

Таблицы хранят категории, события, переводы, источники, ежедневный календарь, игровые сессии и попытки. В вопросах перевод хранится отдельно от исторического события, поэтому добавление `kk` или `en` не требует менять игровую механику.

## Исторический контент

В исходный набор включено **60 событий** с 11 темами. Каждая запись хранит числовой год, эру, точную дату при наличии, вопрос, объяснение, регион, сложность, ключевые слова и как минимум одну ссылку на источник. В наборе есть материалы NASA, ООН, Библиотеки Конгресса США, Национального архива Великобритании, Национального географического общества, Smithsonian, спортивных архивов и энциклопедические страницы.

Цель 500 вопросов пока не достигнута: в начальную версию включены записи с конкретным вопросом и источником, без генерации выдуманных дат ради объёма. Перед публичным запуском редактору следует проверить соответствие каждой формулировки ссылке, уточнить спорные календарные трактовки и утвердить записи в статусе `reviewed`. Для событий до нашей эры эра указывается в вопросе; в игровую клетку вводятся только четыре цифры года.

### Добавление и обновление данных

1. Открой **Редакторам** и скачай полный экспорт JSON.
2. Добавь категорию через форму категорий, если её ещё нет.
3. Добавь или исправь событие. Уникальный `id` нужен для обновления существующей записи. Добавь перевод с `locale: "ru"` и действующий HTTPS-источник.
4. Черновик можно импортировать с `factCheckStatus: "draft"` и `published: false`. Чтобы опубликовать, установи `factCheckStatus: "reviewed"` и `published: true` после проверки источника.
5. Назначь дату из списка опубликованных вопросов. Календарь сохраняет ручное назначение.

Пример записи:

```json
{
  "id": "sample-event-2001",
  "year": 2001,
  "era": "CE",
  "exactDate": "2001-09-11",
  "title": "Название события",
  "question": "В каком году произошло событие?",
  "explanation": "Краткая справка с контекстом.",
  "period": "Новейшая история",
  "category": "recent-history",
  "difficulty": "medium",
  "region": "Мир",
  "keywords": ["событие", "год"],
  "factCheckStatus": "draft",
  "published": false,
  "translations": [
    { "locale": "ru", "question": "В каком году произошло событие?" }
  ],
  "sources": [
    { "title": "Название архива", "url": "https://example.org/source" }
  ]
}
```

`exactDate` допускает год, месяц или полный день. Для дат до нашей эры можно указать строку вида `44 BCE-03-15`. Эра ответа должна быть явно указана в формулировке.

## Настройки и запуск

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `PORT` | HTTP-порт | `4173` |
| `HOST` | Адрес прослушивания | `127.0.0.1` |
| `DATABASE_PATH` | Файл SQLite относительно папки проекта | `./data/hrono.sqlite` |
| `ADMIN_TOKEN` | Токен редактора | Не задан — административный API закрыт |
| `BASE_URL` | Канонический URL и ссылка в результате | `http://localhost:4173` |

`BASE_URL` принимает HTTPS для развёрнутого сайта и HTTP только для localhost. Для публичного развёртывания задай, например, `BASE_URL=https://hrono.example`, оставь Node.js доступным только за TLS reverse proxy и используй длинный случайный `ADMIN_TOKEN`. Сохраняй SQLite на постоянном диске и делай резервные копии файла базы. Не запускай несколько экземпляров с независимыми SQLite-файлами: у них будут разные административные назначения и игровые сессии.

Сбросить локальную базу можно остановив сервер и удалив `data/hrono.sqlite` вместе с файлами `data/hrono.sqlite-wal` и `data/hrono.sqlite-shm`; при следующем запуске она создастся из JSON. Удаление гостевого профиля в интерфейсе удаляет его игровые сессии и попытки из базы.

## Проверки

```powershell
npm test
npm run check
```

Тесты покрывают повторяющиеся цифры, зелёные/жёлтые/серые клетки, некорректный ввод, UTC-планирование, отсутствие ответа в открытом API, победу и поражение, архив, тренировку, права редактора, импорт и экспорт, назначение заданий и удаление профиля.

## Границы текущей версии

- Это одноузловое локальное приложение. Вход по аккаунту, синхронизация между устройствами, OAuth, облачная база и публичные рейтинги не подключены.
- Гостевой `clientKey` является идентификатором устройства, а не подтверждённой учётной записью. Он не защищает личность от намеренной подмены ключа.
- Rate limiting попыток хранится в памяти одного процесса. Для публичного высоконагруженного сервиса следует перенести ограничитель и расписание в общую инфраструктуру.
- Начальный набор меньше ориентира 500; ссылки и формулировки стоит повторно модерировать перед публикацией. Не заявляется нагрузочная ёмкость, которую не измеряли.
- API-интеграция и серверные сценарии покрыты тестами; клиентский скрипт проверен на синтаксис. В этой среде браузер не смог подключиться к локальному порту из-за сетевой изоляции, поэтому фактический экран не удалось проверить автоматизированным браузером. Для просмотра запусти `npm start` и открой адрес в обычной сессии браузера.
